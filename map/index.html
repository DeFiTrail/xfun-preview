脑图 × 源码
包含关系核对

在动任何一行源码之前，先把 X.FUN 脑图上的每一条，和 fist2 现有源码逐条对上， 标清楚哪些已经有了、哪些是有壳没芯、哪些真的要新做。 只有这张表定下来，才谈得上「哪些复用、哪些新增」。

核对方式：脑图 8 条主干逐条展开 → 在 views/ components/ util-web3/ api/ store/ locales/ 全文检索 → 命中后回溯到具体的合约方法、ABI 函数名、组件路径或 i18n 键。 只有能指到具体证据的才算「有」。

有　合约 + 页面都在，换皮即可 半　只展示不计算，或有壳无芯 无　源码里确实没有，要新做 不上页面　线下算，页面只显示结果
●

先说清楚「半」是什么意思，这一档最容易误判

「半」有两种，性质完全不同，混在一起会把工作量估错：

① 只展示不计算 —— 页面上有这个数，但数是后端或合约给的，前端只负责渲染。 比如 V 等级：页面写的是 V{{ stakeData.level }}，等级怎么算前端根本不知道。 换皮不影响它；但反过来说，「脑图写了 X」不等于「合约实现了 X」， 这类条目要跟合约方确认后才能写进新文案。

② 有壳无芯 —— JS 里有封装好的方法，但当前合约 ABI 里根本没有这个函数，也没有任何页面调用。 这是上一个项目留下的死代码。它不算「已有」，但它说明这套代码写过同类东西。

02

机构轮 =「解锁」，它不是一个独立页面

这一条单独拎出来讲，因为它决定了要不要新建目录。

●

源码里「解锁 / 释放 / 领取」本来就是一组共享弹窗，不是页面

全站的解押、释放、领取、提取，都由 src/components/ 下的两组弹窗承担， 被 /stake、/builder、/myassets 反复复用：

components/UnStake/　index.vue 567 行（解押主弹窗，成功提示就是「解锁成功」）
　　　　　　　　　　MyUnStake.vue 555 行　·　Extraction.vue 217 行（待释放一键提取）
　　　　　　　　　　LPUnStake.vue 393 行　·　Dividends-Pop.vue 482 行　·　Liquidity-Pop.vue 264 行
components/PopClaim/　index.vue 601 行　·　LPpopClaim.vue 594 行

所以机构轮要接进来，正确做法是在这组已有弹窗里加一个「机构轮释放」类型 —— 复用同一套「待释放 / 已释放 / 可领取 + 提取」的结构与 release / releasable / myInfos 合约调用， 换一个数据源即可。不新建页面，不新建目录，不动路由。

源码结构：换皮动什么、不动什么

直接回答「会不会改目录结构」——不会。下面是逐目录的明细。

src/ ├── router/routes.ts 不动　16 条路由一条不改，不加不删不改名 ├── util-web3/ 不动　abi.js 9 个合约地址、mint.js、dapp.js、5 个 ABI json 全部原样 ├── api/ 不动　接口路径与出入参不变 ├── store/ 不动 ├── composables/ enums/ utils/ 不动 ├── layout/ 不动结构，只换视觉 │ ├── styles/ 改　新增一层 design token（变量文件），不删旧文件 ├── assets/ icons/ 改　替换图形资源 ├── locales/lang/*.json 改　只改文案值，10 种语言的 key 一个不动 │ ├── views/ │ ├── home/ 换皮　index.vue + 5 个子组件，结构保留，重写 style 与 class │ ├── stake/ 换皮　2995 行，script 逻辑一行不动 │ ├── launch/ builder/ invite/ myassets/ tools/ 换皮同上 │ └── engine/ ★ 新增目录　引擎质押页，唯一新增的 view │ └── components/ ├── UnStake/ 换皮 + 加一个类型　机构轮释放并入这里，不新建目录 ├── PopClaim/ StakingPop/ nav-bar/ … 换皮 └── SmartMoney/ ★ 新增目录　聪明钱造血看板（首页精简版 + 内页完整版）
不动 只改视觉层 新增

换皮具体改哪几层

  • 每个 .vue 的 <style> 块
  • class 命名与 DOM 的装饰性层级（不改带 v-if / v-for / :class 绑定的结构）
  • 全局 token：配色、字号、圆角、间距、阴影
  • i18n 文案值（叙事口径调整时）

一行都不会动的

  • <script setup> 里的业务逻辑与状态
  • 所有合约调用、地址、ABI
  • 所有接口请求与字段名
  • 路由表、路由名、路由参数
  • 已有目录与文件的名字和位置
●

为什么坚持不动结构

这套代码有 2995 行的质押页、2273 行的共建者页，背后是 9 个已经在链上跑着的合约。 改结构就意味着要重新验证每一条链上调用，风险和收益完全不成比例。 换皮的价值在于视觉与叙事，不在于代码整洁度 —— 想重构是另一个项目，不该混在这次里做。
